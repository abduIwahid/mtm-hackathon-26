A hackathon plan, built from its messages - and checked.

Drop in the message pack - emails, WhatsApp notes and notices in English, Urdu and Roman Urdu. The agent reads every message, plans the venue, schedule, food, judging and budget, and proves the plan passes six checks before you ever see it.

Start a new assessment Open the dashboard How it works

One small model reads. Plain code does the arithmetic, the checking and the guarding - so figures are exact and bad updates bounce off.

What gets planned

VENUE

The cheapest room that seats everyone and has every required feature.

SCHEDULE

Blocks that sum exactly to the event length, with every required break placed.

FOOD

One box per person present - students, staff and judges - at the latest quoted price.

JUDGING

Enough judges for every team, honorarium included, judging time that fits the schedule.

BUDGET

Every cost in one total, tested against the cap - with the headroom stated.

How a run flows

STEP 1

Upload the pack

One file, exactly as received. Nothing is pre-filled and no facts live in the code.

STEP 2

The agent reads, code plans

One model call turns the messages into dated facts. Code merges them - newer quotes replace older ones - and builds the plan.

STEP 3

A checked plan, with a trace

Six checks must pass. Every model call is printed with its tokens, and every figure can be clicked back to its source message.

What makes it different

Wrong-message shield

A message that would under-feed the room or break a passing check is rejected with the reason printed - the plan stays valid.

Transactional updates

New messages are applied to a copy first and only committed if every check still passes. No half-broken plans.

Decision evidence

Click the venue, the food or the judging and see the confirming message, what it replaced, and why each alternative lost.

What-if simulator

Venue unavailable? 50 more students? A judge drops out? Simulate it on a copy - the real plan is never touched.

Agent chat

Send updates in plain words, or ask the plan questions. Answers come from the plan's own figures - no model call needed.

Risks, with levers

Thin budget headroom, tight venue, one judge from trouble - each risk is flagged with the exact saving that fixes it.
